`bench/asr-parakeet-vs-whisper` of the user's fork. It's being run on the M3 Air too. Run the

## Intent & Goal

The upstream maintainer (@kajisho5) said on PR #305 / #312 that a Parakeet vs whisper.cpp
comparison "on more material" than LibriSpeech would be welcome as an issue. The user is
fulfilling a commitment they made publicly on #311, so the numbers need to be solid. Two
machines, the fanless M3 Air and the M4 Max, show how much of the result is the chip and how
much is the engine.

**Done when:**
- `bench/asr/results/m4-max/` holds `machine.json`, `timings.jsonl`, the SRTs, `report.md` and
  `summary.json`;
- `report.md` has a WER and a time for every one of the 6 sets × 5 configs, with no `n/a` and
  no errors;
- the results are committed on `bench/asr-parakeet-vs-whisper`, unpushed.

## Learnings & Landmines

- **Never re-run `pick_clips.py`.** It rewrites `manifest.json`, and then the two machines no
  longer score the same audio. Use `prep.py` only.
- **The WAVs should be byte-identical to the M3's.** After `prep.py`, compare the clip counts and
  the first 16 hex characters of `shasum -a 256 data/<set>.wav`:

  | set | clips | sha256 (first 16) |
  |---|---|---|
  | librispeech | 109 | d92326b3f033bd7d |
  | ami | 381 | 4df39868a5f9a6c7 |
  | earnings22 | 184 | 7546069641cb608f |
  | gigaspeech | 147 | e971727e3f396e8c |
  | voxpopuli | 77 | 489cdbc3e2cf66dc |
  | common_voice | 111 | 0289f0486e6aa4be |

  The M3 built these with FFmpeg 9.0.2. A different FFmpeg could produce different bytes from
  the same source audio. If a checksum differs but the clip counts match, carry on and record
  it in the commit message and `report.md`. Don't "fix" it with a re-selection.
- **Run it detached.** A run takes roughly 30–75 minutes, longer than a foreground tool call is
  allowed to run, and a backgrounded tool call can be killed. Use `nohup … &` with a log file,
  as in Next Steps, and watch the log.
- **The first M3 attempt was lost:** the laptop was unplugged mid-run and slept. `run.py` now
  stops if it finds itself on battery, and the run goes under `caffeinate -ims` so it can't
  idle-sleep. Keep the lid open and stay plugged in. If it stops for battery, delete
  `results/m4-max/` and start again.
- **Keep the machine idle and on AC power during the timed run.** No test suites, builds or
  other ASR jobs. The 2026-09-27 benchmark on this machine had timings that overlapped a test
  run.
- **`run.py` clears `FFMPEG_SKILL_ASR_ENGINE`, `PARAKEET_MODEL`, `PARAKEET_CPP_MODEL` and
  `FFMPEG_SKILL_HW` on purpose.** Each config names its engine and model explicitly. Don't
  re-export them.
- **Don't add configs to the run,** for example Parakeet v3 or whisper `small.en`, which this
  machine also has. That changes the rotation order and stops the two machines being
  comparable. If extra configs are wanted, run them afterwards under a separate label such as
  `m4-max-extra`.
- **Models `run.py` expects** (it skips and records any that are missing):
  - `~/.cache/whisper.cpp/ggml-{base,small,large-v3-turbo}.bin`;
  - `parakeet-mlx` on PATH, with `mlx-community/parakeet-tdt-0.6b-v2` in the Hugging Face
    cache (the warm-up pass may download it; timed passes run offline);
  - `parakeet-cli` on PATH, plus `~/.cache/parakeet.cpp/tdt-0.6b-v2-*.gguf`.
  - On this machine `parakeet-cli` is a **wrapper** in `~/.local/bin`, and the real binaries
    are in `~/.local/libexec/parakeet.cpp/`. Don't move them.
- **Dead end already hit:** the clip picker was first called `select.py`. That shadows Python's
  standard `select` module and breaks `subprocess` when `run.py` runs. It's renamed; don't name
  any file in `bench/asr/` after a stdlib module.
- **Git rules (user-global):**
  - Never `git push`; the user pushes.
  - Never push to upstream (`kajisho5`); only `origin`, the fork.
  - No "Generated with", "Co-Authored-By" or session lines in commit messages.
  - Keep this branch's tracking unset, or pointed at `origin`.
- **Reviews:** if you run a Codex review, use `gpt-5.6-luna` xhigh, one review at a time.
  Never use the Haiku model for subagents.

## Next Steps

1. **Get the branch** (run from the repo root, `~/projects/ffmpeg-skill`):
   ```sh
   git fetch origin
   git worktree add ../ffmpeg-skill-wt-bench -b bench/asr-parakeet-vs-whisper origin/bench/asr-parakeet-vs-whisper
   cd ../ffmpeg-skill-wt-bench && git branch --set-upstream-to=origin/bench/asr-parakeet-vs-whisper
   ```
2. **Pre-flight checks:**
   - `pmset -g batt | head -1` should show AC Power;
   - list the models from Learnings: `ls ~/.cache/whisper.cpp ~/.cache/parakeet.cpp`, then
     `command -v parakeet-mlx parakeet-cli whisper-cli uv ffmpeg`;
   - `ffmpeg -version | head -1`.
3. **Build the data:** `uv run bench/asr/prep.py`. Then compare clip counts and checksums
   against the table in Learnings.
4. **Run it detached and watch it:**
   ```sh
   nohup caffeinate -ims python3 bench/asr/run.py --label m4-max --runs 3 > bench/asr/run-m4-max.log 2>&1 &
   ```
   Then follow `bench/asr/run-m4-max.log` (Monitor with an until-loop, not foreground sleeps).
   Every line should end without `exit …`.
   - If a config errors, read the log line. Fix the environment (a missing model, for
     example), not the harness.
   - Then delete `bench/asr/results/m4-max/` and run it again.
5. **Score it:** `uv run bench/asr/score.py m4-max`. Read `report.md` and sanity-check it:
   - whisper base should have the highest WER;
   - large-v3-turbo and Parakeet v2 should be the lowest on LibriSpeech, roughly 2–3%.
6. **Commit:**
   ```sh
   git add bench/asr/results/m4-max && git commit
   ```
   Use a message like `bench(asr): M4 Max results`, giving the headline numbers and any
   checksum differences. Don't push.
7. **Report back to the user:**
   - the overall WER and RTFx for each config;
   - whether the checksums matched;
   - anything odd;
   - the exact push command for them to run:
     `git push -u origin bench/asr-parakeet-vs-whisper`.
